# Notes for Claude

## Keep the README plain-language

After every change to the product, update `README.md` so it reflects what the app does now and what's next.

- Write for someone who isn't technical: no programming terms, file names, commands or acronyms (say "works offline and can be added to your home screen", not "PWA").
- Describe what a person can do and see, not how it's built.
- Keep the Progress table current.
- Technical details (setup, tests, how the checks work) go in `DEVELOPERS.md`, not the README.
- If you propose a repository description, keep it plain-language too. The current one is: "Find out if your furniture fits in a new home before you move."
